## 4. Notes on specific columns

- `sensor_46` (*Active power - generator connected in star*) and `sensor_49` (*Reactive power - generator connected in star*) are **constant zero across all 1,196,747 raw observations**. They carry no information. Phase 1 removed them; this analysis base retains them so the check is reproducible, but they must be excluded before modelling.
- `sensor_14_avg` (*Temperature in generator bearing 1, Non-Drive End*) and `sensor_22_avg` (*Actual phase displacement*) are the only columns with missing values: 20 each in the raw data. No imputation has been applied in the analysis base - the gaps are left visible so that Phase 3 can decide how to treat them.
- `row_id_in_event` is the raw `id` column, renamed. It is a **per-file row counter that restarts at 0 in every event file**. `event_info.csv` indexes into it via `event_start_id` / `event_end_id`. It is meaningless once files are merged and must never be used as a feature.
- `status_type_id` has **no documented meaning** in the supplied files. See `reports/status_analysis.md`.
- Angular signals are flagged `is_angle=True` in the documentation: `sensor_1`, `sensor_2`, `sensor_5`, `sensor_42`. These must not be averaged or differenced naively - they wrap at 360 deg.
- Counter signals: the documentation flags `is_counter=True` for no signal.
